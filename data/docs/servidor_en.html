Setting up a Puerto Bravo server

A server is a small program you leave running so several people can play together in the same city. It saves the characters, the gangs and the neighborhoods, and it decides what happens between players. It doesn't need a powerful machine, and it works just as well for two friends as for a hundred people or more.

Everything can be done with the keyboard and a screen reader: there is a panel with a window for Windows and, on any system, the server can be run through text.

You can move through this guide by headings. Each way of setting it up has its own section, with the steps one by one. You don't need to read all of it: pick your way in section 3 and go to it.

1. What you need

  • A computer that stays on while people play: your PC, an old laptop, a NAS, a Raspberry Pi or a rented server.
  • On Windows you don't need to install anything: the server comes with the game.
  • On Linux, Mac, NAS or Raspberry Pi you need Python 3.8 or later, which is almost always already installed. You don't need to install anything else: the server only uses what comes with Python. You don't need the game there.
  • For people outside your home to join: open a port on the router, or use a private network. It's explained in section 13.
  • It uses very little: with a few players you barely notice it in the processor or the memory.

2. What's in the servidor folder

Inside the game folder there is a folder called servidor. Everything for the server is there, and everything it saves goes there. Game updates don't touch your configuration or your data.

  • Panel del servidor.bat (Server panel): opens the panel window. It's the easiest option on Windows.
  • Servidor por consola.bat (Console server): starts the server in a text window.
  • Parar el servidor.bat (Stop the server): stops the running server in an orderly way.
  • Arrancar con Windows - activar.bat (Start with Windows - enable) and Arrancar con Windows - quitar.bat (Start with Windows - remove): to make it start by itself when you sign in.
  • documentacion_es.html and documentacion_en.html: this guide, in Spanish and in English.
  • servidor.conf.ejemplo: all the options, explained one by one.
  • otros_sistemas: what you copy to a Linux machine, a Mac, a NAS or a Raspberry Pi. It contains the server code, the scripts arrancar.sh, parar.sh, reiniciar.sh and estado.sh, the systemd service puertobravo.service, and the Docker files: Dockerfile, docker-compose.yml and entrada_docker.sh.

When you start the server for the first time, these will also appear:

  • servidor.conf: your configuration.
  • datos_servidor: the characters, the gangs, the certificate and, inside it, the copias folder with the backups.

The server programs for Windows are in the game folder, next to the game: PuertoBravoServidorPanel.exe, the panel, and PuertoBravoServidor.exe, the console. Both always work with the servidor folder, wherever you open them from.

3. Choosing how to set it up

  • You want to play with some friends from your Windows PC and you want it to be easy: the panel, section 4.
  • You prefer a text window, or you're going to leave it running unattended: the console, section 5, and starting it automatically, section 6.
  • You have a computer with Linux, or you rent a server: sections 7 and 8.
  • You have a Raspberry Pi: section 9.
  • You have a Mac: section 10.
  • You use Docker: section 11.
  • You have a Synology NAS: section 12.

The configuration and the data are the same in all of them: you can start on your PC and move the server to another machine later. Section 20 tells you how.

4. On your Windows PC, with the panel

Starting it for the first time

  1. Open the game folder, go into the servidor folder and open Panel del servidor.bat. You can also open PuertoBravoServidorPanel.exe directly, in the game folder.
  2. The panel window opens, with the focus on the server status, which will say it's stopped.
  3. If you want to change something before starting, press Control+P to open the settings. The minimum is to give your server a name, on the first tab. Press OK to save.
  4. Press F5 to start. The first time it takes a few seconds, because the server creates its certificate to encrypt the connection.
  5. When it's done, the panel says "Server running" and the port. If Windows asks whether you allow the program to communicate over the network, say yes: without that, nobody can join.
  6. The Status tab shows the address you have to give to anyone playing in your own home. The Copy the address button puts it on the clipboard.
  7. Join first yourself from the game: the first account that joins is the admin.

The tabs

You switch tabs with Control+Tab and Control+Shift+Tab.

  • Status: whether it's running, how many people are on, the port, the address for your friends, the encryption with its fingerprint, and the world it's working with. One thing per line. It updates by itself only when something changes, without moving the cursor from where you have it; F6 updates it right away.
  • Players: who is on, where, and with which version of the game. With the buttons, or with the Applications key on a player, you can send them a message, kick them, ban them or make them admin.
  • Accounts: every account that has ever joined. From here you can ban, pardon a ban, give or remove admin rights and delete an account, even if the person isn't on.
  • Invitations: the invitation codes, free and used. You create, copy and cancel them here.
  • Log: what the server says as it goes, with the newest at the end. Below it there is a field to type commands to it, the same ones as in the console.

Panel keys

  • F5: start the server. Shift+F5: stop it. Control+F5: restart it.
  • Control+P: settings. Control+Q: quit.
  • Control+N: announcement to all players. Control+M: message to the selected player. Control+E: kick the selected player.
  • Control+I: create an invitation. Control+D: change the message of the day. Control+O: type a command.
  • F6: update the status and the lists.
  • Control+S: save now. Control+B: backup now. Control+R: restore a backup. Control+G: save the log to a file.
  • F1: open this guide. Control+H: explains the control you're on.
  • Alt plus the underlined letter: go to a control on the tab or open a menu.
  • Applications key, or Shift+F10, in the player and account lists: actions on the selected item.

The settings

  • Control+P opens a dialog with one tab for each group of options. Control+H on any control tells you what it does, what values it accepts and whether it needs a restart.
  • OK saves and closes. Apply saves without closing. Cancel changes nothing.
  • Factory defaults resets the options on the tab you're on, or all of them, to how they come out of the box. Nothing is saved until you press OK or Apply.
  • Almost everything is applied with the server running. If you change something that needs a restart, like the port or the encryption, the panel tells you and offers to restart right then.
  • The configuration is saved in servidor.conf, a text file with each option explained, which you can also change with Notepad.

Stopping and closing

  • Shift+F5 stops the server: it warns the players, saves everything and disconnects them. If there are people on, it asks first.
  • If you close the panel with the server running, it asks and, if you say yes, it stops the server in an orderly way before closing.
  • The server only works while the panel is open. You can minimize it.
  • Control+F5 restarts it: players are told it's a restart, and their games wait and rejoin by themselves as soon as it starts again.
  • If you update the game with the panel open, the panel closes by itself, in an orderly way, and opens again when the update finishes, with the server running again if it was. It's in section 20.

5. On your Windows PC, from the console

  1. In the game's servidor folder, open Servidor por consola.bat.
  2. The first time, it writes servidor.conf with all the options explained, and starts with the default values.
  3. The window tells you what's happening: which port it's listening on, whether it encrypts, who joins and who leaves.
  4. You type commands to it in that same window. Type help and press Enter to hear them all. They're in section 16.
  5. To change the configuration, open servidor.conf with Notepad, change what you want and save. Then type reload in the console: it applies what can be changed without restarting and tells you what is waiting for the restart.
  6. To stop it, type shutdown, press Control+C or close the window. In all three cases it warns the players and saves everything.

The panel and the console use the same configuration and the same data: you can use one on one day and the other on another day, but not both at once.

If you know how to use a command window, you can call the program directly from the game folder:

  • PuertoBravoServidor.exe --ejemplo: writes servidor.conf and exits.
  • PuertoBravoServidor.exe --comprobar: checks servidor.conf, tells you what isn't valid and exits.
  • PuertoBravoServidor.exe --opciones: lists all the options with their explanation.
  • PuertoBravoServidor.exe --parar: stops the running server in an orderly way.
  • PuertoBravoServidor.exe --actualizar: stops it, warning the players that it's restarting to update. Their games wait and rejoin by themselves when you start it again.
  • PuertoBravoServidor.exe --reiniciar: the same, saying it's for maintenance.
  • PuertoBravoServidor.exe --puerto=47821: any option can be given like this, without touching the file.

6. Starting it automatically with Windows

When you sign in

  1. In the servidor folder, open Arrancar con Windows - activar.bat. It leaves a shortcut in your user's Startup folder. You don't need administrator rights.
  2. From then on, every time you sign in, the server starts by itself, in a minimized window.
  3. To stop it without looking for that window, open Parar el servidor.bat.
  4. To stop it from starting by itself, open Arrancar con Windows - quitar.bat.

When the computer turns on, without anyone signing in

This is for people with a dedicated computer. You need an account with administrator rights.

  1. Open Windows Task Scheduler: press the Windows key, type Task Scheduler and press Enter.
  2. In the Action menu, choose Create Task.
  3. On the General tab, name it Puerto Bravo Server and check Run whether user is logged on or not.
  4. On the Triggers tab, press New and choose At startup.
  5. On the Actions tab, press New. In Program/script, put the full path of PuertoBravoServidor.exe, which is in the game folder. In Add arguments, type servidor.conf.
  6. On the Settings tab, uncheck Stop the task if it runs longer than, so it doesn't get cut off after three days.
  7. Press OK. Windows will ask for your account password so it can start the task without a session.

Started this way it has no window. To stop it in an orderly way use Parar el servidor.bat, and to run it, the commands from the game chat, which are in section 16. If you choose End in Task Scheduler, it's cut off abruptly: you lose no more than the last minute, but it's better to stop it in an orderly way.

7. On Linux or a rented server, with Python

  1. Check that you have Python 3.8 or later: type python3 --version.
  2. Copy the game's otros_sistemas folder to the machine, with any name you like, for example puertobravo inside your home folder. Any way of copying files works: a USB stick, scp, or a file transfer program.
  3. Go into that folder: cd puertobravo. The servidor folder, with the code, must be inside it.
  4. Write the example configuration: python3 -m servidor --ejemplo. It creates servidor.conf.
  5. Change it as you like with a text editor, for example nano servidor.conf. To check there are no errors: python3 -m servidor --comprobar.
  6. Start it: python3 -m servidor. It tells you which port it's listening on and whether it encrypts. You type commands to it in that same terminal; help lists them all. You stop it with shutdown or with Control+C.

Leaving it in the background

  • sh arrancar.sh: starts it in the background, if it's not already running. What it says as it goes is kept in servidor.log.
  • sh estado.sh: tells you whether it's running and shows the last thing it said.
  • sh parar.sh: stops it in an orderly way.
  • sh reiniciar.sh: warns the players with the countdown, stops it in an orderly way and starts it again. This is what you use after putting in the new server code: the games wait and rejoin by themselves.
  • To make it start when the machine turns on without systemd, add a line like @reboot sh /home/tu_usuario/puertobravo/arrancar.sh to your cron, with crontab -e.
  • Started this way it has no console. You run it from the game chat, with the commands in section 16.

The firewall

  • If the machine has a firewall, you have to let the server port through over TCP. With ufw: sudo ufw allow 47820/tcp. With firewalld: sudo firewall-cmd --permanent --add-port=47820/tcp and then sudo firewall-cmd --reload.
  • On a rented server there is usually also a firewall in the provider's control panel, sometimes called a security group: open port 47820 over TCP there too.
  • A rented server has a fixed public address: there's no router to configure. The address for your people is puertobravo://, the machine's address, a colon and the port.

8. On Linux, as a systemd service

This way it starts by itself with the system, restarts if it crashes and stops in an orderly way when the machine shuts down. You need to be able to use sudo.

  1. Copy the server folder to /opt/puertobravo: sudo cp -r puertobravo /opt/puertobravo. The servidor folder must end up inside it.
  2. Create an unprivileged user for it: sudo useradd --system --home /opt/puertobravo puertobravo.
  3. Give it the folder: sudo chown -R puertobravo: /opt/puertobravo.
  4. If there's no configuration yet, write it: cd /opt/puertobravo and sudo -u puertobravo python3 -m servidor --ejemplo. Change it with sudo -u puertobravo nano servidor.conf.
  5. Copy the service: sudo cp /opt/puertobravo/puertobravo.service /etc/systemd/system/.
  6. Enable it: sudo systemctl daemon-reload and then sudo systemctl enable --now puertobravo.
  • See how it's doing: systemctl status puertobravo.
  • Hear what it says as it goes: journalctl -u puertobravo -f. You exit with Control+C.
  • Stop it: sudo systemctl stop puertobravo. Start it: sudo systemctl start puertobravo. Restart it, for example after changing the port: sudo systemctl restart puertobravo.
  • If you use another folder or another user, change the WorkingDirectory and User lines in the service file.
  • As a service it has no console: you run it from the game chat.
  • Restarting it with a warning, for example after updating it: an admin types /reiniciar or /actualizar in the game chat, or on the machine, from the server folder, sudo -u puertobravo python3 -m servidor --actualizar. The server warns with its countdown, saves everything and exits with code 75; the service starts it again by itself after five seconds, and the games rejoin.

9. On a Raspberry Pi

  • Any model with Raspberry Pi OS works: it already comes with Python 3. For a few friends, the most modest model is more than enough.
  • The steps are the same as on Linux: sections 7 and 8. The most practical thing is to leave it as a systemd service, so it starts by itself when you turn it on.
  • To copy the otros_sistemas folder you can use a USB stick, or scp from your computer if you have SSH enabled on the Raspberry Pi.
  • On the slowest models, checking the identity of whoever joins takes a little over a second. It only happens when joining; while playing you don't notice it.
  • Give the Raspberry Pi a fixed address on your network from the router settings, in the address reservation or static DHCP section. That way the address you give your people doesn't change, and the port forwarding keeps pointing to it.
  • Use a good-quality memory card and leave automatic backups turned on: cards wear out.

10. On a Mac

  1. Open Terminal and type python3 --version. If the Mac offers to install the developer tools, accept: they include Python. You can also install Python from its official website.
  2. Copy the otros_sistemas folder to the Mac, for example to your home folder with the name puertobravo.
  3. In Terminal: cd ~/puertobravo, then python3 -m servidor --ejemplo and, once you've changed servidor.conf as you like, python3 -m servidor.
  4. The first time, the Mac asks whether you allow incoming connections to Python: say yes.
  5. To leave it in the background the same scripts work: sh arrancar.sh, sh estado.sh, sh parar.sh and sh reiniciar.sh.
  6. To stop the Mac from going to sleep while people are playing, look in System Settings, in the energy or battery section.

11. With Docker and docker compose

  1. Copy the otros_sistemas folder to the machine where you have Docker, with the name puertobravo. Inside it are Dockerfile, docker-compose.yml, entrada_docker.sh and the servidor folder.
  2. Go into that folder and type docker compose up -d --build. It builds the image and starts the server.
  3. The datos folder appears next to it. Inside are servidor.conf, which is written automatically the first time, and datos_servidor, with the characters and the backups. They're outside the container: they survive updates.
  4. To change the configuration, edit datos/servidor.conf and restart: docker compose restart.
  • Hear what it says: docker compose logs -f. You exit with Control+C, without stopping the server.
  • Stop it in an orderly way: docker compose down. It warns the players and saves everything.
  • Type commands to it: docker attach puertobravo, type the command and press Enter. To leave without stopping it, press Control+P and then Control+Q. The easiest way is to run it from the game chat.
  • Don't use the shutdown command inside Docker to stop it: Docker would start it again. Use docker compose down.
  • To restart it with a warning, the restart and update commands do work, from the game chat or with docker attach: the server warns with its countdown, saves everything and exits, and Docker starts it again. The games wait and rejoin by themselves.
  • If you change the port in servidor.conf, also change both numbers on the ports line of docker-compose.yml.
  • With Docker, all connections may reach the server from the same internal address. That's why the conexiones_por_ip option must stay at 0.

12. On a Synology NAS

With Container Manager

Container Manager is Synology's Docker package. You install it from Package Center, and it creates a shared folder called docker.

  1. Open File Station, go into the docker shared folder and create a folder inside it called puertobravo.
  2. Upload the whole content of otros_sistemas to that folder: the servidor folder, Dockerfile, docker-compose.yml and entrada_docker.sh. The other files don't get in the way.
  3. Open Container Manager and go to the Project section.
  4. Press Create. For the project name put puertobravo. In Path, choose the docker/puertobravo folder.
  5. Container Manager sees that there's already a docker-compose.yml there and asks whether to use it: say yes.
  6. Continue with Next to the end, without enabling the web portal, and press Done. It builds the image and starts the server. The first time it takes a few minutes.
  7. The configuration ends up in docker/puertobravo/datos/servidor.conf. You can change it from File Station with the Text Editor package. Then, in Container Manager, Project, choose puertobravo and, in Action, Stop and then Start.
  8. What the server says is in Container Manager, Container, puertobravo, Log tab.
  • If you have the NAS firewall turned on, in Control Panel, Security, Firewall, add a rule that allows port 47820 over TCP.
  • Give the NAS a fixed address on your network, or reserve one for it in the router, so the port forwarding doesn't stop pointing to it.
  • To update the server: upload the new servidor folder on top of the old one and, in the project, choose Action, Build. The datos folder is not touched.

Without Docker, with the NAS's own Python

  1. Install the Python 3 package from Package Center, if you don't have it.
  2. Copy the content of otros_sistemas to a folder on the NAS, for example puertobravo inside a shared folder.
  3. In Control Panel, Task Scheduler, create a Triggered Task of type User-defined script, with the Boot-up event and with your user, not with the system administrator.
  4. In the script, type sh, a space and the full path of arrancar.sh. For example, sh /volume1/docker/puertobravo/arrancar.sh.
  5. To start it right away, without restarting the NAS, select the task and press Run.
  6. To stop it, create another task just like it, with no event, with parar.sh, and run it when needed.

13. The address you give your people, and how to connect from outside your home

What the address looks like

  • It's puertobravo://, the machine's address, a colon and the port. For example, puertobravo://192.168.1.50:47820.
  • In the game you add it in Play on a server, Add a server.
  • If you haven't changed the port, which is 47820 by default, you can give the address without the colon and the port.

For people playing in your own home

  • The machine's address on your network works; it usually starts with 192.168. The panel tells you on the Status tab and copies it with the Copy the address button.
  • On Windows you can also find it by opening a command window and typing ipconfig: it's the IPv4 Address line. On Linux, with hostname -I.
  • If the server is on the same computer you play on, you can join with puertobravo://127.0.0.1.

For people playing from outside: opening the port on the router

From the internet, only your router can be seen. You have to tell it to pass whatever arrives at the server port to the machine where the server is. This is called opening a port, redirecting a port or port forwarding.

  1. Give the server machine a fixed address on your network. On the router it's usually in the local network or DHCP section, with a name like address reservation or static DHCP.
  2. Go into the router settings from your browser. The address is usually 192.168.1.1 or 192.168.0.1, and the username and password are on a sticker on the router itself.
  3. Look for the ports section. Depending on the brand it's called Ports, Port redirection, NAT, Virtual server or Port forwarding.
  4. Add a rule: TCP protocol, external port 47820, internal port 47820 and, as the destination, the address of the server machine on your network.
  5. Save. Some routers ask to restart.
  6. Find out your public address: the router shows it on its status page, with a name like internet IP address or WAN. That one, with puertobravo:// in front, is the one you give your people.

Opening it automatically, with UPnP

  • Many routers let a program on your network ask them to open a port. This mechanism is called UPnP.
  • In the panel, with the server running, go to the Manage menu and choose Open the port on the router with UPnP. If the router allows it, the port is opened and the panel tells you; when you stop the server it closes by itself.
  • If the router doesn't answer or refuses, it has UPnP turned off or doesn't support it. You can turn it on in its settings, or open the port by hand as explained above.
  • The console server and the Linux one don't open the port by themselves: there you have to do it by hand.

If your public address changes: dynamic DNS

  • In many homes the public address changes from time to time. So you don't have to tell your people every time, you use a name that always points to your current address. That's dynamic DNS.
  • There are free services that provide it. Many routers and NAS devices have a section called DDNS or dynamic DNS to keep it up to date by themselves.
  • With the name, the address for your people becomes, for example, puertobravo://minombre.ejemplo.net:47820.

If you can't open ports

  • Some providers don't give each home its own public address: several homes share one. This is called CG-NAT. You can tell because the WAN address your router shows doesn't match the one shown by the websites that tell you your address. In that case opening the port doesn't help. You can ask your provider to take you off CG-NAT, or use a private network.
  • A private network, like the ones Tailscale or ZeroTier create, connects the computers you choose over the internet as if they were in the same home, without opening any port. You and each person who is going to play install the program and join the same network. Each computer gets an address inside that network.
  • The address for your people is then puertobravo:// and the address the private network gives the server machine. With Tailscale it starts with 100.
  • Only people on your private network can join: it's also a way to have a server just for your group.
  • Another way out is to rent a small server, which has its own public address: section 7.

14. Encryption and certificate

  • By default, with cifrado = auto, the connection is encrypted. The server creates its own certificate the first time it starts. You don't need to install anything, on Windows either.
  • The certificate and its key are kept in the data folder, in certificado.pem and llave.pem.
  • When it starts, the server says its certificate's fingerprint, and the panel shows it on the Status tab. It's a string of letters and numbers that identifies it.
  • Each player's game remembers the server's certificate the first time it joins. If one day the server presents a different certificate, the game warns and doesn't join without permission: someone might be pretending to be your server.
  • That's why, if you move the server to another machine, take certificado.pem and llave.pem with the data: that way nobody sees a warning. Backups include them.
  • If you really do change the certificate, tell your people that the game will ask them, and that they should accept the new one.
  • If you have your own certificate, put the paths of its files in the certificado and llave options. It's not necessary: the game doesn't check the certificate's name, only that it's always the same one.
  • With cifrado = si, the server doesn't start if it can't encrypt. With cifrado = no, it never encrypts: that only makes sense for tests in your own home.
  • The certificate key is secret. Don't share llave.pem or your backups.

15. Who can join

  • Each player has an identity that their game creates and that never leaves their computer. The server recognizes them by it: there are no account passwords to remember or to steal.
  • The entrada option decides who can create a new character. Anyone who already has a character can always come back in.
  • abierta: anyone who has the address.
  • clave: you need to know the entry password, which you set in the clave option. The game asks for it the first time.
  • invitacion: you need a single-use code. You create them in the panel with Control+I, or with the invitar command. Each code is good for one character only.
  • The max_jugadores option says how many people fit at once. With 0 there's no limit. Admins get in even if it's full.
  • To keep someone out: in the panel, the Ban button; through text, the vetar command and their name. You lift it with Pardon the ban or with the perdonar command. There's also a list of banned names in the configuration, in the vetados option.
  • To free up space on full servers, the inactividad_minutos option removes anyone who has spent that long doing nothing. Their character stays saved.

16. Running the server

Who runs it

  • The first account that joins a new server is the admin. Normally that's you: join first.
  • You appoint more with the panel's Make admin button, with the admin command and the name, or by putting their names in the admins option, separated by commas.
  • You take it away with the Remove admin rights button, on the Accounts tab, or with the quitaradmin command.

Where you give commands from

  • From the panel: with its buttons and menus, or by typing them in the Command for the server field, on the Log tab.
  • From the console: by typing them in the server window.
  • From the game, if you're an admin: in the general chat, which opens with F10, with a slash in front. For example, /players or /announce Gang war tonight. The game tells the answer to you alone. This is how you run a server that has no console: a service, a container or a NAS.

The commands

Since version 1.7.3 every command works in English and in Spanish, at the same time and whatever the server's language: help or ayuda, players or jugadores, kick or expulsar, ban or vetar, shutdown or apagar, and so on for all of them. The help lists them in the console's language: in English, with the Spanish one in brackets. And with rename name: new name you change an account's player name without it losing anything; since 1.7.3 nobody joins for the first time without a player name, so accounts like "Player 3" are no longer needed.

  • help (ayuda): lists all the commands.
  • status (estado): how the server is doing: port, encryption, world, uptime and how many people there are.
  • players (jugadores): who is online and where.
  • accounts (cuentas): all the server's accounts, with the banned ones and the admins.
  • announce (aviso) text: says something to everyone who is online.
  • tell (decir) name: text: says something to one player only.
  • kick (expulsar) name: kicks a player; they can come back in. After a colon you can tell them the reason.
  • ban (vetar) name: kicks a player and does not let them come back.
  • unban (perdonar) name: lifts the ban.
  • op (admin) name: makes a player an admin.
  • deop (quitaradmin) name: takes away their admin rights.
  • rename (renombrar) name: new name: changes an account's player name, without losing anything; if they are online, they rejoin with the new one.
  • deleteaccount (borrarcuenta) name: deletes an account with its character, its properties and its place in the gang; it cannot be undone.
  • invite (invitar): creates a single-use invitation code; with a number after it, creates several.
  • invites (invitaciones): the invitations there are, free and used.
  • revoke (anular) code: cancels an invitation nobody has used yet.
  • motd (mensaje) text: changes the message of the day; with no text, removes it.
  • time (hora) number: sets the game time, from 0 to 23.
  • gangs (bandas): the gangs, with their people and their till.
  • save (guardar): saves everything now.
  • backup (copia): makes a backup.
  • backups (copias): the backups there are.
  • reload (recargar): reads servidor.conf again and applies what can be changed without restarting.
  • update (actualizar): warns everyone that the server is restarting to update, waits for the countdown, saves everything and stops it; the games wait and come back in on their own when you start it again. You can add the seconds of warning after it.
  • restart (reiniciar): the same, but saying it is for maintenance. You can add the seconds of warning after it.
  • shutdown (apagar): warns everyone, saves everything and stops the server.

Player names are typed as they are, with their spaces. For example, expulsar Ana la Rápida or decir Ana la Rápida: turn the music down.

17. Playing with different versions of the game

People with different versions of the game can play together on your server. Nobody is kicked for being behind or ahead: someone is only refused because of their version if you ask for it, with the minimum version. And from there, everyone is kept as even as possible.

The world is brought by the first one to join

The server manages, but the content comes from the game. The world, with its places, its weapons, its vehicles and its missions, isn't tied to the server: it's given by the game of whoever joins.

  • The server that ships with the game already includes the world of its version. If you set it up without it, or delete it, it starts empty and takes the world of the first one to join.
  • If the first one to join has an older version and later someone arrives with a newer one, the server switches to the world of the newer version, without restarting and without kicking anyone. It announces it to whoever is on. It only does this if that world is signed by the game's publisher, so nobody can sneak a modified world into it.
  • If it's the other way around, and someone arrives with a version older than the server's, the server keeps its world, which is the newest, and that person joins anyway.
  • The server knows the world of the already released versions out of the box, and it remembers the ones it checks along the way: it asks nothing of anyone who arrives with one of them.
  • If the server is empty and the first one to join has mods, or plays with an unsigned copy, their world is taken for the time being, a warning goes in the log, and it's replaced by the first signed one that arrives.

What happens when not everyone has the same thing

  • Damage, range, rate of fire and money are decided by the server, with the figures of its world, the same for someone shooting with one version and someone getting hit with another. Having the new version gives no advantage.
  • A weapon someone's game doesn't have reaches them as the closest thing their game knows: they hear the shot of one of their own weapons of the same class and take the damage the server sets. For example, for someone playing with 1.7.0, the 1.7.1 pump-action shotgun sounds like one of their shotguns.
  • A vehicle they don't have is heard going by and seen parked as the closest one of theirs, with the name its owner gave it. On the server it's still what it is.
  • Giving a weapon to someone who doesn't have it in their version isn't possible: the server gives it back to whoever was giving it, and tells them.
  • The roleplay channels reach an older game through the usual chat, with a few words in front saying what they are.
  • Restart warnings reach them as a normal warning, and the shutdown, with a text their game reads as it is. Their character is saved all the same.
  • If the server's world is from an older version (because you don't want new worlds, or because nobody with the new one has joined yet), the new weapons of whoever has them count against other players as bare hands, their new vehicles are seen as a compact car, and in a new town nobody sees them. That person is told.
  • When joining, anyone who doesn't have the same data as the server is told, by name, which weapons and which vehicles don't match and what they'll notice. It's also on the game's phone, Online, Data and rules of this server.

The character, from one version to another

The character is saved on the server in full, including what the server doesn't know. If someone plays with a new version and one day joins with an older one, they lose nothing:

  • Their old game receives the character without the weapons or vehicles it doesn't know. They're still saved on the server, and the player is told.
  • When that game saves, the server puts back everything the old version can't save. Whatever they've earned, spent or obtained while playing with the old one counts.
  • When they join again with the new version, they have everything again.

What you decide

  • version_minima: the oldest version that can join. Empty, which is the default, any version. It's the only way to refuse someone because of their version.
  • mundo_distinto: what to do with someone who brings data that can't be checked, which is almost always someone with mods that change the world. With admitir, the default, they join and play with what's shared: they're told what doesn't match, and whatever their mod changes or adds doesn't count against the others. With rechazar, they don't get in.
  • actualizar_mundo: who can bring a new world. With firmado, the default, anyone, if it's from a real version. With admin, also an admin without a signature: that's what you need for your whole server to play with a mod. With no, the server keeps the world it has.
  • versiones: with compatibles, the default, everything in this section. With iguales, only someone with exactly the same data as the server gets in.
  • comprobar_datos = no lets anyone in without checking anything, and the server doesn't update to new worlds. You don't need it to play with different versions.

Good to know

  • In the panel, the player list says which version each person joined with.
  • You don't need to update the server every time a version of the game comes out. A 1.7.0 server accepts 1.7.1 games, but it can't give each game the closest match or restore the character: anyone who joins it with a version older than the server's won't hear the others' new weapons. Update it when you can.
  • To make your whole server play with a mod, set actualizar_mundo = admin and have an admin join first with the mod enabled. Anyone who joins without the mod will play anyway, with what they have in common.
  • What only exists in the new version and doesn't go through the server (a new mission, a new shop, a new trade) is available to whoever has that version, like any other new feature of the game. Whatever gives money goes through the server's caps, whatever the version.
  • If a new version moves the streets of a town that already existed, anyone still on the older one will see the server's traffic moving where there's no longer a street, until they update.

What's new on the street in version 1.7.1, on a server

Since version 1.7.1, for solo play, the game has patrols that do their rounds without looking for anyone, an optional police helicopter and the option to surrender with your hands up. With shared police, which is the policia option set to si, none of that is turned on in each player's game: the patrols are the server's, and there's no helicopter and no surrendering. With that option set to no, each player has them according to their own options, and only they see them. The ambulances that come after a shootout and the neighborhood war mode on the street don't count on a server either. Self-defense does: if someone defends themselves from a gang member who attacked them first, their game doesn't record the crime.

18. Players' money: the hourly cap and the jobs

With the economia option set to si, which is how it comes, the server keeps track of each player's money so nobody can make it up with a hacked game. Spending is always allowed. Earning depends on where the money comes from.

What the server accepts with no limit

  • What the server itself gives: loot between players, sales of houses and businesses, the gang's funds, the pay for helping in a group mission.
  • What another player gives.
  • The reward for each story mission, only once.

Repeatable jobs

Board contracts, gym fights, bank and store robberies and car jobs can be done again and again. The server recognizes them without using up the hourly earnings, with two limits:

  • encargos_hora: how many are recognized per hour, of each type. By default, 6.
  • encargo_max: the most that is accepted from the pay of a single one. By default, 15,000 euros. On top of that, the server knows from the game data the most each type of job can pay, and doesn't recognize more than that.

A player who goes over that number in an hour is warned, and that job counts as ordinary earnings. Anyone playing with a version older than 1.7.1 doesn't tell the server about their jobs: for that person, everything counts against the hourly earnings, as before, until they update.

Everything else: the hourly earnings

Everything else you earn playing on your own (jobs, sales, gambling, street loot) has a cap per clock hour, the ganancia_hora option, which is 30,000 euros by default. Whatever goes over the cap is taken away, and the player is told with figures: how much they earned, how much is accepted, what the cap is, and at what rate they get margin back.

  • Unused margin builds up, up to the hours set by ganancia_acumula, which is 3 by default. That way, someone who hasn't earned anything for a while can have a whole good run without losing money. It also builds up while the player is away.
  • Someone joining for the first time starts with a quarter of an hour of margin. Leaving and joining again doesn't refill it.
  • The player can check how it's going on their phone: Online, Data and rules of this server.

Permanent contracts and their paychecks

Since version 1.7.1 the game has permanent contracts: you sign them at the job center, they ask for a number of shifts every seven game days and they pay a paycheck at the end of each period. On a server, the paycheck is paid by the server, so nobody can make it up:

  • The server counts the shifts, keeps the calendar and sets the amount, which comes from the game data. What each player's game says about how much they earn doesn't count.
  • The paycheck doesn't use up the hourly earnings. What you earn for each shift does, like any job.
  • nominas: with no, there are no permanent contracts on your server. By default, there are.
  • nomina_max: the most you pay for a paycheck. By default, 1,500 euros, which doesn't cut any of the game's paychecks; it's there so a mod can't make them skyrocket.
  • nomina_turnos_dia: how many shifts you count for each player in one game day. By default, 3.
  • Asking to be paid early, repeating it, or leaving and joining again gives nothing: the contract and its pay date are saved on the server.
  • The server's world must be from 1.7.1 or later. Anyone playing with 1.7.0 has no permanent contracts, neither here nor playing solo.

Of the rest of the game's honest life, on a server you have the academy diplomas, which only cost money; the criminal record, which counts for jobs of trust; and, if you leave trato_prestigio set to si, a small discount in shops for those with a good name and a surcharge for those with a very bad one, the same for everyone. Loans, mortgages, taxes and business management don't exist: they create or move money the server can't check. The game tells the player.

What to set on your server

  • Among trusted friends: raise ganancia_hora without fear, to 100,000 or more, or turn off money tracking with economia = no. The cap is there for servers open to strangers, not to spoil things for your people.
  • On an open server: leave the default cap and, if your people live off contracts or robberies and complain, raise encargos_hora before ganancia_hora.
  • If someone tells you the server is taking money from them, ask them what the game told them: since 1.7.1 it gives them the figures. The server log shows a line each time, with what was taken away and the cap.
  • All these options can be changed with the server running.

If the connection drops right after buying

The character is saved on the server every three quarters of a minute and, since 1.7.1, a few seconds after a purchase: two or three seconds after the first one and, if the player keeps spending, at most every twelve. If even so someone's connection drops before their game saves, the server puts back into their balance what they spent since the last save: what they bought isn't on their character, but the money isn't lost either. A line appears in the log. It can't be used to make money: what was given to another player, what the server charged and houses bought don't come back.

19. Text roleplay, voice and vehicle radio

Role-play channels

With the rol option set to si, which is how it comes, players have, besides the usual chat:

  • A channel to talk in character. Only those nearby hear it: closer than the meters set in rol_metros, which is 30 by default.
  • A command to tell what their character does. Whoever types "opens the door" makes those nearby hear their name and "opens the door". It has the same range.
  • A channel to talk out of character, as a player. The whole server hears it.
  • A profile line, up to two hundred letters long, that says who their character is. The others read it whenever they want.

Each channel has its own sound in the game, and everything said can be reviewed on the phone, Online, Role-play. In the game it works like this:

  • Shift F10 talks in character, and Control F10 describes an action. F10 on its own is the usual general chat. Players with a controller have them in the actions menu, and can type with the letter wheel or pick one of the ready-made phrases.
  • In any message you can type a command in front: slash yo and what the character does; slash ep and what is said in character; slash fp and what is said out of character; and slash ficha and the profile line. For example, /yo abre la puerta.
  • Another player's profile is read on the phone, Online, Who is here, by picking them; or with Shift J when they are near you.
  • Players with a version older than 1.7.1 do not have those channels in their game, but they are not left out: what is said in character and the actions reach them through the nearby chat, with a few words in front that say what they are, and they can use the slash commands from their general chat.
  • With rol = no there are no role-play channels or profiles, and the usual chat remains. It can be changed with the server running: whoever is already in finds out when they try to use them.
  • Admin commands are still typed in the chat with a slash in front. The four role-play commands are for everyone; the rest, only for whoever administers.
  • The server does not keep what is said on any channel. The profile line is kept, with each player's account.

Voice

The game has no microphone voice chat. If on your server you want to talk out loud while you play, which is usual on role-play servers, use a separate voice program: any of the ones for group calls over the internet will do, and there is nothing to set up on the server or in the game. A tip if you use a screen reader: put the others' voices through a speaker or headphone other than the reader's, or turn their volume down, so they don't talk over each other.

Radio in other players' vehicles

With the radio_coches option set to si, which is how it comes, whoever is near another player's vehicle hears, faint and muffled, the station it has on, and stops hearing it when moving away.

  • It only works for the stations that come with the game. Nothing is shared about "My music" or the stations each player makes with their own files: neither the music nor the name leaves their computer.
  • Only the short name of the station goes through the server, a few letters. No sound goes through: each game plays its own copy of that station, so it may not be the same song the driver hears.
  • Each player can turn it off in their Options, in Sound and music. With radio_coches = no nobody hears it.
  • Players with an older version neither hear it nor let others hear theirs.

20. Backups, moving the server and updating it

Backups

  • By default, the server makes a backup every 24 hours and keeps the last 7. It is changed with the copia_auto_horas and copias_guardar options.
  • They are in the copias folder, inside the data folder. Each backup is a zip file.
  • To make one right now: in the panel, Control+B; in text mode, the copia command. The ones you make are not deleted automatically.
  • A backup holds the database with the accounts and characters, the world the server was working with, the certificate with its key, and the configuration.
  • Because it holds the certificate key and the configuration, a backup is not for sharing: keep it where only you can see it. It is a good idea to have one somewhere other than the server machine.

Restoring a backup

  • In the panel: Control+R, choose the backup and press OK. If the server is running, it stops it first. What is there at that moment is saved in another backup, just in case, with a name that starts with antes_de_restaurar.
  • You can tick an option to also restore the configuration inside the backup. If you don't tick it, the current one stays.
  • By hand, on any system: stop the server, unzip the zip inside the data folder, letting it replace the files, and start it. The backup's servidor.conf file goes next to the data folder, not inside it.

Moving the server to another machine

  1. Stop the server.
  2. Copy servidor.conf and the whole data folder, datos_servidor, to the new machine. Or make a backup and take the zip with you.
  3. On the new machine, set up the server as its section says and put those files in place: on Windows, in the game's servidor folder; on Linux, next to the code's servidor folder; with Docker, inside the datos folder.
  4. Start it. The characters, the gangs and the certificate are the same: nobody notices the change, except for the new address.

Updating the server

Since version 1.7.1, updating no longer throws anyone back to the menu. The server warns the players with a countdown, waits for each game to save its character, saves everything and closes saying why. The games stay on a waiting screen, with the game session as it was, and when the server comes back, they wait and come back in on their own: everyone carries on where they were.

On Windows

  • Just update the game, with the server or the panel open. There is no need to stop it first.
  • The game says you have the server open, explains what is going to happen and asks for permission. If you say yes: it warns the players, the server stops on its own, the game closes and updates, and when it finishes the server starts again on its own, just as it was: the console one in its window, minimized, or the panel, with the server running if it was.
  • If you only have the panel open, with the server stopped, even if you have never started it, there is nobody to warn: the panel closes on its own and opens again at the end, stopped as it was.
  • The console server and the panel come back minimized and without taking focus: the focus stays on the game. When you go to the panel, the focus is on the server status, as always.
  • If the update fails, the version you had is kept and the server is started again anyway. What the server saved when closing is not lost: the update only saves and restores programs, never your database.
  • When it opens, the game says whether the server has started again. Everything is written to the actualizacion.log file in the game's data\logs folder.
  • If the server starts on its own when you sign in, with Arrancar con Windows (Start with Windows), it also starts again on its own.
  • If you have it set up as a service or as a scheduled task that runs without anyone signing in, the game can ask it to close, but cannot start it the way Windows starts it: it warns you before starting, and afterwards you will have to start it the way you have it set up, if it does not come back on its own.
  • Your configuration and your data are not touched, whether the update goes well or fails, whether they are in the default data folder or in another one you set. The only thing that does not work is having the data folder inside one of the program's own folders, such as lib: if the game sees that, it says so and does not update until you move it.

On Linux, Mac, NAS, Raspberry Pi or Docker

There the server is not updated with the game: you replace its code by hand. So that players get the same wait and the same return, stop it with the restart command instead of cutting it off:

  1. Replace the code's servidor folder with the one from the new game's otros_sistemas folder. It can be done with the server running: it does not read the new code until it starts again. Do not touch servidor.conf or the data folder.
  2. Restart it with a warning. Depending on how you have it set up:
    • With the scripts: sh reiniciar.sh. It warns, stops it and starts it again.
    • With systemd or with Docker: an admin types /actualizar in the game chat. The server warns, closes with code 75, and systemd or Docker start it again on their own. With Docker, if you have also changed the image, type docker compose up -d --build: when the container stops, the server still tells the games it is coming back.
    • By hand, with the console in front of you: type update, wait for it to finish and start it again.
    • Without a console: from the server folder, python3 -m servidor --actualizar. Or leave a text file called parar.txt in the data folder with the word update inside: the server checks it every second, deletes it and obeys. With restart it says it is for maintenance, and with parar it just stops. After the word you can put the seconds of warning, for example actualizar 60.
  • The countdown is the one in the parada_aviso option, 20 seconds by default. How long it waits for each game's last save is set by parada_espera.
  • When the server stops in order to come back (the update and restart commands), its program ends with code 75. If whoever runs it stops it (shutdown, Control+C), it ends with 0 and the games go back to the menu, as always.
  • If the system stops it (systemctl stop, docker compose down, sh parar.sh, shutting down the machine), there is no time for a countdown, but the server still tells the games it is a restart: they wait and come back in on their own if it returns before they give up, which is ten minutes by default.
  • Players with version 1.7.0 hear the warning as a normal notice and, when the server closes, go back to the menu with a text saying the server is restarting and to come back in a few minutes. Their character is saved all the same.

In all cases

  • New options work with their default value even if your servidor.conf does not have them. If you save the configuration from the panel, the file is rewritten with all of them. Options a server does not know are let through, and it says so when starting.

21. Servers with lots of people

  • There is no fixed player cap. With max_jugadores = 0 everyone who arrives gets in.
  • What weighs the most, on the processor and above all on the network, is telling each player where the others are. That is why those close to them are reported ten times per second; for the others in their town, it tells them roughly where they are once per second; and for those in other towns, every two seconds. If there is a crowd around, it reports less often per second.
  • The distance within which others are followed in detail is set by the radio_detalle option, 150 meters by default. If the connection is tight, lower it to 100. Don't set it to 0 with lots of people: with 0 everything is reported, to everyone, all the time.
  • As a guide, what the server sends each player just for the others' positions: with ten players, about 3 KB per second; with a hundred spread over a town, about 25; with a hundred all together, about 40. Multiplied by the players, a hundred people means between 2.5 and 4 megabytes per second of upload. Shared traffic, pedestrians and police add a bit more.
  • The server's traffic and pedestrians appear by zones, wherever there are players. The caps per town are trafico_total and peatones_total. If the machine is struggling, lower them, or turn off the shared traffic, pedestrians or police: each game will put in its own.
  • With lots of people, what runs short first is a home internet upload, not the computer. For a large server, rent a machine with a good connection.
  • On Linux, each player takes up an open connection. The systemd service already raises the limit. If you start it by hand with more than about a thousand people, raise the limit first with ulimit -n 65536.
  • Turn on inactividad_minutos so that whoever has gone away without leaving does not take up a slot.
  • Saving every minute with thousands of accounts is barely noticeable, but you can space it out with guardado_minutos.

22. Troubleshooting

The server does not start

  • "Could not open port": the server is already running in another window, or in the panel and the console at the same time, or another program is using that port. Close the other one, or change the puerto option.
  • "Encryption is mandatory but there is no certificate": you have set cifrado = si and the certificate could not be created. Set cifrado = auto, or check that the data folder can be written to.
  • It says there are problems in the configuration: each warning says which option it is and why it is not valid. The server starts anyway, with that option's default value. With --comprobar it is checked without starting.

Nobody can get in

  • First try yourself, from the same computer, with puertobravo://127.0.0.1. If you get in, the server is fine and the problem is in the network.
  • If someone in your home cannot get in: check that they use your local network address and not the public one, and that the firewall on the server machine lets the port through. On Windows, it asks the first time; if you said no, you have to allow it in Windows Security, Firewall, Allow an app.
  • If someone outside cannot get in: check the router rule, that it points to the current address of the server machine and that it is TCP. Also check that you gave them your current public address, and if you are behind CG-NAT, section 13.
  • From inside your home, many routers don't let you in using your own public address. It is not a fault: from home, use your local network address.

What the game says when trying to get in

  • "The server is full": raise max_jugadores or set it to 0.
  • "The entry password is not correct" or "that invitation code is not valid": entry is by password or by invitation. Give them the password, or a new code.
  • "You cannot come into this server": that account is banned. It is lifted with Pardon the ban.
  • "Your game's data is not this server's": they have mods that change the world, or an unsigned game, and you have mundo_distinto set to rechazar or versiones set to iguales. By default, that person gets in. Section 17.
  • "This server has just been set up and does not have the game data yet": the server is empty and could not take the world from whoever is coming in, almost always because you have actualizar_mundo set to no. Section 17.
  • "This server requires version such-and-such of the game or later": you have set the version_minima option.
  • "The server does not present the same certificate as last time": you have changed the certificate, for example by reinstalling without taking the data with you. Section 14.
  • "Too many connections from your address": you have set the conexiones_por_ip option and several players share an address. Raise it or set it to 0.

Other things

  • After updating the game, the server has not started again: the game says so when it opens, with the reason, and it is written to actualizacion.log, in the game's data\logs folder. Usually it was set up as a Windows service or task: start it the way you have it set up. If not, open it yourself from the servidor folder.
  • Players stay waiting and do not get in: they wait at most what each of them has set in their options, ten minutes by default, and try every few seconds. If the server comes back requiring a newer version of the game (version_minima), their game tells them and offers to update.
  • Someone has money taken away: the server keeps track and does not accept what is earned faster than ganancia_hora allows. Since 1.7.1 the game tells them the figures. What counts, what doesn't and what is best to set is in section 18.
  • I have lost admin rights: stop the server, put your player name in the admins option and start it.
  • I want to start from scratch: stop the server and delete or move away the data folder. A new one is created on startup, with a new certificate.
  • To ask for help, save the log: in the panel, Control+G. It holds nothing personal except player names, and the addresses if you turned on registro_ip.

23. What the server keeps

  • For each player: their public key, which is a number that identifies them; the name they chose; their character; and the game version they last came in with.
  • It does not keep emails, account passwords or network addresses.
  • The network address of whoever connects is only written to the log, and only shown in the panel, if you set registro_ip = si. By default, no.
  • Chat messages are not kept, not even those on the role-play channels. The profile line each player writes is, with their account, and it is deleted with it.
  • From vehicle radios only the short name of a game station goes through the server, and it is not kept.
  • The entry password, if you use one, is written in servidor.conf: don't share that file.
  • If you run a server open to strangers, you are responsible for their data: tell your people and delete the account of anyone who asks you to. It is done with the Delete the account button, in the panel's Accounts tab, or with the borrarcuenta command and the name.

24. All the configuration options

Each option goes on one line of servidor.conf, in the form nombre = valor (name = value). Lines that start with a hash sign are comments. In the panel they are in Settings, Control+P, each group in its own tab.

Most apply with the server running: from the panel, when you accept; in text mode, with the reload command. Some rules, such as traffic, police, pedestrians, combat, adult content and prices, reach each player's game when they come in: whoever is already in will fully notice them when they come back in. The ones that need a server restart say so.
